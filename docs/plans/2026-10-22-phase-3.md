## Goal
Every Phase 3 box in `docs/ROADMAP.md` is met on `main`:
- The six GDD buildings exist, are placed with a ghost (valid and invalid tint, confirm and
  cancel), block their tiles, have power, and can be destroyed.
- A build sidebar with three tabs, queues, cost and progress, a power bar and low-power effects
  works in landscape and portrait (ADR 0015 §5), with the minimap in it.
- Ore fields regrow; harvesters run the loop to the refinery; credits rise.
- All six MVP units can be produced, and rally points send them on.
- A match ends in victory, defeat or a draw, with a result screen.
- A dummy opponent builds a base and defends it, through Commands like a player.
- The portrait box: the battle screen follows ADR 0015 §5 with the real sidebar band; the Android
  build follows the sensor through `docs/plans/2026-10-19-portrait.md`'s last row, P64.

Then Michael runs the gate ("Gate procedure"): a full match against the dummy on his phone, and the
perf budget still met on two cards, the Phase 2 perf arena and the new base arena (ADR 0021).

## Sim data model and Command changes
ADR 0017 fixes the layout and ADR 0018 the rules. The hard rules hold for every row of this table:
integers only (credits, ore, progress in hundredths of a tick, milli-tile positions); 15 Hz; no
random draw anywhere in Phase 3's sim rules; every change through a Command or a sim rule on hashed
state; every number in `data/*.tres`; the view reads only the snapshot. Loops visit players, tabs,
rows (ascending id) and ore cells (ascending) in a fixed order.

| Topic | State | Commands | Phase | Hash (ADR 0016) | Kernels (ADR 0013) |
| --- | --- | --- | --- | --- | --- |
| Buildings as rows | rows with a footprint type (speed 0, radius 0, armour `BUILDING`); `World.add_building` blocks `move_cost`, bumps `map_version`, invalidates the flow cache; `remove_dead` unblocks | `PLACE` (10) | COMMANDS, REMOVE | rows as today; `move_cost` through the map digest | none changed; a building-world case in every kernel lockstep (P71) |
| Placement validity | `Placement.reason` over `PlacementInput` (map, terrain, `terrain_buildable`, `move_cost`, `explored`, rows) | `PLACE` | COMMANDS | reads hashed state only | none |
| Power | `power_made`, `power_used` per player | - | ECONOMY | derived, out, rebuild test | `Combat.fire` (GDScript) skips offline defences; TARGETING unchanged |
| Ore fields | `ore_cell` (map), `ore_amount` | - | ECONOMY (regrowth) | `ore_cell` in the digest, `ore_amount` hashed | none |
| Harvesters | `harvest_mode`, `cargo`, `harvest_slot`, `home` (row columns) | `HARVEST` (14); unit-group orders set IDLE | ECONOMY | hashed | none (orders through `Movement.reset_row`) |
| Refinery | building with a dock and a free harvester | `PLACE` | COMMANDS | as rows | none |
| Credits | `credits` per player | `QUEUE` pays, `CANCEL` refunds | COMMANDS, ECONOMY (unload) | hashed | none |
| Production queues | `queue_type`, `queue_count`, `queue_progress` per player and tab | `QUEUE` (11), `CANCEL` (12) | PRODUCTION | hashed | none |
| Rally points | `rally_x`, `rally_y` per player and tab | `RALLY` (13) | COMMANDS, PRODUCTION | hashed | none |
| Victory and defeat | `defeated_tick`, `stat_*` per player; `match_end_tick`, `winner` | `SURRENDER` (20) | PRODUCTION (`Outcome.run`) | hashed | none |
| Last seen buildings | `ghost_*` records per player (World, not `FogGrid`) | - | MEMORY | hashed, live entries | none |
| Derived lists | `building_rows`, `harvester_rows` | - | ECONOMY | derived, out, rebuild test | none |

- **Tick order** (ADR 0017 §5): the Phase 2 pipeline unchanged, then ECONOMY (11), PRODUCTION (12)
  and MEMORY (13), then `tick += 1`. `SimProbe.Phase.COUNT` becomes 14.
- **One hash re-pin:** P70 declares everything at once (`STATE_FORMAT` 3, sections `players`,
  `ore`, `ghosts`), under exception 10, after P65. From P70 on the perf arena's golden hashes and
  hash bytes stay constant: P65q's `WATCH sim hash_bytes` line must show the same min and max on
  every later Phase 3 row (ADR 0017 §7 estimates +1.2 to +3.1 KB per checkpoint at P70).
- **Kernels:** the new phases start as GDScript; the lead applies ADR 0013 §1's clauses at P93's
  `PERF bases` line and §15's trigger on the gate cards (ADR 0021 §4). A row that finds it needs a
  kernel change edits both twins with a lockstep case (ADR 0013 §5) and says so in its PR.

## View and touch UX
ADR 0019 decides the UI; ADR 0015 §5 the layout in both orientations. In short:
- **Sidebar** (P85, P85b): right zone in landscape, bottom band in portrait (20 %, at least 200
  dp); credits and power bar, three tabs (icon-only in the band), item tiles of at least 64 dp with
  cost, progress, count and a state shape (available, locked, unaffordable, ready). Tap queues, a
  long-press cancels one (refund), a ready structure opens placement. P85 sets the portrait zone's
  height through P61's one place, so the ArmyBar moves above the band; the bottom stack stays at
  most 40 % of the safe height, the band giving way first.
- **Placement** (P86): ghost at the view centre's tile; green with a solid outline or red with a
  hatch and a reason glyph, from `Placement.reason` on the snapshot; a drag that starts on the ghost
  moves it 64 dp above the finger (ADR 0019 question 1, option B), other drags pan; check mark and
  X of 64 dp in the sidebar zone; pending and "Blocked" states; a turn keeps the ghost's tile and
  sends nothing.
- **Map** (P84, P84b, P87): buildings with team layers and health bars; ore cells by amount;
  harvesters; selecting an own building opens its tab; a ground tap with a barracks or factory
  selected sets the rally flag; harvesters plus a tap on ore harvest; "All army" and mixed boxes
  leave harvesters out.
- **Minimap** (P88): top of the sidebar in landscape, right end of the band in portrait; one
  texture at fog cadence; tap or drag jumps the camera, a long-press with units selected moves them.
- **Low power and under attack** (P89): dimmed consumers, offline glyph on defences, a pulsing
  power bar; edge arrows and minimap pings for own rows hit off screen.
- **Result screen and surrender** (P90): Victory, Defeat or Draw with the per-player stats;
  "Play again" and "Back"; a "Surrender" button with a confirm dialog at the top left.
- **Where a match starts** (P90): Dev → Skirmish (ADR 0019 question 4). The preview's main scene
  keeps `data/scenarios/controls_test.tres`, so the Phase 1 and 2 scene suites keep theirs.
- Every UI row tests at the six sizes of ADR 0015 §6 and the portrait profiles, with screenshots
  in the PR.

## Dummy opponent
ADR 0020: `DummyAi` (ai-dev) reads only a `PlayerView`, thinks every 15 ticks on a tick whose step
does not hash, inside `TickJob.run` before `loop.step` (on the worker in `WORKER`), and appends
Commands that `MatchLoop` stamps and records. It follows `data/ai/dummy.tres`: a build order,
a fixed placement spiral around its Headquarters, a harvester target, and a defence radius it never
leaves. It never attacks. No random number, no bonus, no hidden information.

## Risks
- **Flow-field churn:** every placement and building death invalidates all cached fields; with
  frequent building the FLOW slice may lag and units start late. The base arena measures it; a
  local invalidation would need a new ADR.
