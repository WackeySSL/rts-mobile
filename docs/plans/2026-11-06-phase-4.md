## Design summary
- **The AI** (ADR 0030): `OpponentAi` with five managers (`AiEconomy`, `AiProduction`, `AiIntel`,
  `AiArmy`, `AiStrikes`) over one `AiMemory`. `think_period` 5, `think_tick` 6, three slots
  (ECONOMY, ARMY, INTEL), so each manager runs once a second and a tick carries a third of the AI;
  players 1 to 4 never think on a checkpoint tick. Counted work caps and at most four flow-cache
  keys per AI, all from data; a CI WATCH line and a phone key show the time.
- **Difficulty** (ADR 0030 §6, §8): `AiDifficultyDef` per level, one code path, no vision ever;
  no money bonus unless answer 1 C's trigger fires (setup data, no state hash or golden move).
- **Data:** `OpponentDef` per faction (roles, weights, build orders by tier, caps),
  `AiBuildOrderDef` per faction and tier, `AiDifficultyDef` per level, all in `data/ai/`.
- **The harness and the report** (ADR 0031): the same loop with `AiFactory`, full matches to
  13 500 ticks, `AUTO`, counting by type from `world.events`, `flow_full_ticks`, schema 2, new
  optional flags, a GDScript merge and summary, a markdown for the issue.
- **The balance run and the gate run** (ADR 0031 §5, §6): Actions only, sharded, posted on the
  `balance` issue by a job that runs no repository code; tuning reads seeds 1-100, the gate reads
  held-out seeds 1001-1100.
- **Hashes:** no sim rule changes. P171 and P171b freeze every pinned input (the two arenas, the
  controls test map, the hand-built Worlds' rules) so tuning never moves a golden.

  budget as it is (the scout's price is not held back). A seen type counts toward the counter
  once its first sighting (`seen_first_tick`) is `reaction_ticks` old, and then with its latest
  count (`seen_count`).

## Risks
- **Stalemates and timeouts** (AI-vs-AI turtles behind defences): `all_in_tick`, growing waves and
  targets from the outcome rule's buildings; the gate fails on any timeout, and every balance run
  flags them every night.
- **Seeds that do not vary the match:** the AI draws on purpose (ADR 0030 §5); the summary's
  `distinct_final_hashes` flag catches it.
- **Seat bias:** player 1 is always the top seat, its Commands come first in a tick and it thinks a
  tick earlier; the gate measures the top seat's share and the balance run's mirrors show it per
  faction. A cause in the sim's command order is a sim ADR, never a quiet reorder.
- **The flow cache** (8 slots, keyed by goal cell and move class): two AIs at four keys each fill
  it before tankers and fights, and a unit without a slot steers straight and can stall. The cap
  counts keys (ADR 0030 §4); `flow_full_ticks` is measured from P188 on; the remedies are
  `goal_keys_max` 3 or P194, chosen from that count, not assumed.
- **The AI's time on the phone:** the 1.0 ms watch rests on a CI estimate (ratio 5.9); P185 measures
  it. Over it, the remedies of ADR 0030 §4.
- **Statistics:** 100 matches decide 40-60 % to about two standard deviations per check (one fair
  run in ten misses check 1 or 2); the gate reads held-out seeds; the one re-run is part of
  Michael's answer 1 A to ADR 0031, fixed before any run.
- **Tuning churn in tests:** P171 and P171b take every pinned hash and rule suite off shipped data;
  exception 20 lists the suites that stay on it. A tuning row that breaks more than its pins stops
  and asks the lead.
- **Kill attribution** is an estimate (last shooter); proposals read it beside survival and share.
- **verify time:** about a minute more (estimate, ADR 0031 §2); P186 and P189 read CI's figure.
- **`PerfHud.gd` at 995 lines:** P184 first; it also frees room for the deferred P66b.
- **Save and resume** (Phase 5) of a match against the AI needs `AiMemory` written out; it keeps to
  ints so that is a small row then.
- **JSON numbers:** Godot's `JSON.parse` returns floats; the merge casts with `int()` and the
  report holds ints only.
- **A dropped Command from the AI** fails the smoke and with it every PR's verify: each manager
  checks its Commands as the dummy does, and P186's harness names the seed and tick.
- **The balance run's token:** `post` holds `issues: write` and runs no repository code; `summarise`
  runs the ref's GDScript with read-only permissions.
- **Scope:** expansions, harassment, spectating, menus and AI surrender stay out ("Out of scope").
- **Legal:** no name, personality, doctrine or build order from Command & Conquer, Red Alert or any
  other game; no code from EA's release or OpenRA (ADR 0030 §10). Review checks names in each AI
  row.
