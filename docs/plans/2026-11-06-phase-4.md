## Design summary
- **The AI** (ADR 0030): `OpponentAi` with five managers (`AiEconomy`, `AiProduction`, `AiIntel`,
  `AiArmy`, `AiStrikes`) over one `AiMemory`. `think_period` 5 and three slots (ECONOMY, ARMY,
  INTEL), so each manager runs once a second and a tick carries a third of the AI; no think on a
  checkpoint tick. Counted work caps from data; a CI WATCH line and a phone key show the time.
- **Difficulty** (ADR 0030 §6, §8): `AiDifficultyDef` per level, one code path, no vision ever;
  money per question 1 (setup data, no golden move).
- **Data:** `OpponentDef` per faction (roles, weights, build orders by tier, caps),
  `AiBuildOrderDef` per faction and tier, `AiDifficultyDef` per level, all in `data/ai/`.
- **The harness and the report** (ADR 0031): the same loop with `AiFactory`, full matches to
  13 500 ticks, `AUTO`, counting by type from `world.events`, schema 2, new optional flags, a
  GDScript merge and summary, a markdown for the issue.
- **The nightly and the gate run** (ADR 0031 §5, §6): Actions only, sharded, posted on the
  `balance` issue; the gate set is 100 crossed Normal-vs-Normal matches with a retry rule fixed in
  advance.
- **Hashes:** no sim rule changes. P171 freezes the arenas' defs so tuning never moves a golden.

## Risks
- **Stalemates and timeouts** (AI-vs-AI turtles behind defences): `all_in_tick`, growing waves and
  targets from the outcome rule's buildings; the gate fails on any timeout, and the nightly flags
  them every night.
- **Seeds that do not vary the match:** the AI draws on purpose (ADR 0030 §5); the summary's
  `distinct_final_hashes` flag catches it.
- **Seat bias:** player 1 is always the top seat, its Commands come first in a tick and it thinks a
  tick earlier; the gate measures the top seat's share and the nightly's mirrors show it per
  faction. A cause in the sim's command order is a sim ADR, never a quiet reorder.
- **The flow cache** (8 slots) under two AIs with four goal points each plus tankers and fights: a
  waiting field makes units stall. `goal_points_max` bounds the AI's share; if the nightly shows
  stalls (units idle with an order), a larger `flow_cache_size` is a rules change for real matches
  only (the arenas' frozen rules keep 8), with a perf check, through its own row.
- **The AI's time on the phone:** the 1.0 ms watch rests on a CI estimate (ratio 5.9); P185 measures
  it. Over it, the remedies of ADR 0030 §4.
- **Statistics:** 100 matches decide 40-60 % to about two standard deviations; the retry rule is
  fixed in ADR 0031 §6 before any run.
- **Tuning churn in tests:** P171b moves the rule suites off shipped data; exception 20 covers the
  pins that stay. A tuning row that breaks more than its pins stops and asks the lead.
- **Kill attribution** is an estimate (last shooter); proposals read it beside survival and share.
- **verify time:** three full matches add under a minute (estimate); ADR 0031 §2's fallback.
- **`PerfHud.gd` at 995 lines:** P184 first; it also frees room for the deferred P66b.
- **Save and resume** (Phase 5) of a match against the AI needs `AiMemory` written out; it keeps to
  ints so that is a small row then.
- **JSON numbers:** Godot's `JSON.parse` returns floats; the merge casts with `int()` and the
  report holds ints only.
- **A dropped Command from the AI** fails the smoke and with it every PR's verify: each manager
  checks its Commands as the dummy does, and P186's harness names the seed and tick.
- **Scope:** expansions, harassment, spectating, menus and AI surrender stay out ("Out of scope").
- **Legal:** no name, personality, doctrine or build order from Command & Conquer, Red Alert or any
  other game; no code from EA's release or OpenRA (ADR 0030 §10). Review checks names in each AI
  row.
