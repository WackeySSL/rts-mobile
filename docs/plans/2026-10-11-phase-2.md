Lessons from Phase 1 that shape this plan:

  first-commit sizes of about 300, and a first commit above 330 lines is split before review.
- All PRs code against one contract table.

- At most two lanes run at once.
- Each PR names its phone check, or says none.
- Michael approves merges with "merge Px" (a batch such as "merge P27-P29" is fine, Phase 1
  answer 9).
- Tests pin every contract number literally, never derived from the same `.tres` (P1 review).

## Goal
Every Phase 2 box in `docs/ROADMAP.md` is met on `main`:
- The sim runs at 15 Hz with World v1, Command v1, DetRandom, a state hash every second and a
  replay test that reproduces the final hash.
- Units path around rock and water with flow fields, and do not overlap (separation).
- Three unit types (light tank, rifle squad, rocket squad) fight with hitscan and projectiles.
  Damage depends on armour class, and dead units are removed.
- Fog of war (visible and explored) is drawn on the map and hides unseen enemies.
- The view interpolates units and projectiles at the display frame rate with no per-frame
  allocation.
- `tests/perf/` runs 150 units for 900 ticks, prints ms per tick and fails above
  `tests/perf/budget.cfg`.

Then Michael runs the gate (see "Gate procedure"):
- the dev scene "Perf arena" on his phone shows 60 fps with 150 units;
- the final state hash on the phone (APK and web) equals CI's for the same commit.

Out of scope (each needs a plan change first): buildings, production, economy, heavy tank,
artillery, harvester, splash damage, AI, minimap, sound, info card, save and resume, writing
replays to disk.

## Interface contracts (all PRs code against these)
Every `class_name` script is PascalCase, everything else snake_case (ADR 0002 §2). "milli" means
milli-tiles, a "cell" is a tile index `(y / 1000) * map_cols + x / 1000`, and "row" is an index
into the per-unit arrays (ascending id). All sim classes `extends RefCounted` unless noted.

## Risks
1. **GDScript is too slow on the phone.** The mock tick is 0.7 ms on the cloud VM, and the real
   sim is estimated at 1.5-2.5 ms. ARM may be 2-3 times slower.
   - Mitigation: amortised cadences (targeting 1/5 per tick, fog one player per tick, flow
     fields sliced), measured early (P49, P50) with an ordered list of remedies (ADR 0011 §6).
     GDExtension is the last resort, through an ADR.
2. **Render cost of 450 sprites plus effects.** Batching through `z_index` layers is not
   verified.
   - Mitigation: the perf arena measures it in P50. MultiMesh is the prepared fallback.
3. **Silent int32 truncation and int64 wrap-around** (verified behaviour) would break
   determinism or game logic without an error.
   - Mitigation: the ADR 0007 §1 rules, contract review of every stored quantity's range, and
     tests with values near map limits.
4. **Cross-platform determinism** (wasm, arm64, x86_64) is assumed from integer-only maths and
   little-endian SHA-256 input.
   - Mitigation: the gate compares the hashes on all three.
5. **Phase 1 behaviour drifts** (separation, combat or terrain change what Phase 1 tests pin).
   - Mitigation: an open map takes the Phase 1 code path exactly (line clear), the controls
     spawns stay, the test area stays open, and the Phase 1 suites must stay green unedited.
6. **CI timing noise fails the perf test.**
   - Mitigation: a 2x budget, only mean and p95 enforced, no retries, and a calibrated budget
     through an ADR if noise is proven.
7. **The sim spine is serial** (`Sim.step` and `World` are shared).
   - Mitigation: World v1 declares every array up front, phase modules live in their own files,
     standalone modules sit in lane B, and only one-line conflicts in `Sim.step` remain.
8. **Balance starting values break the counter triangle** after truncation or range effects.
   - Mitigation: the triangle test is the judge, values may change in P42 with the table
     updated, and real balance is Phase 4.
9. **Michael's phone is faster than the 2021 target.**
   - Mitigation: the card records the model, and open question 1 sets stricter numbers.
10. **Flow cache churn** if many distinct blocked orders happen at once.
    - Mitigation: lazy fields only when a line is blocked, a graceful fallback to `DIRECT`, and
      the size in data.
11. **Scope creep:** no artillery, heavy tank, buildings, minimap, sound, info card or smooth fog
    shader. Each needs a plan change first.
12. **Long PR list (26 PRs).**
    - Mitigation: small standalone PRs, batch merge approvals (Phase 1 answer 9), and two lanes
      from day one.
