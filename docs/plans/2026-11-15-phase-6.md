## Goal
- `AdService` with a fake mode that tests, the editor, the web preview and the dev APKs use; the
  Poing AdMob plugin on the Play build; caps from `data/ads_settings.tres`; gameplay never waits
  for an ad that has not shown.
- UMP consent before any ad request; "Privacy options" in settings when UMP requires it.
- Rewarded offers by the player's choice (Double XP, +500 starting credits next match); a capped
  interstitial between matches; banners in the menus and at the open pause menu's foot.
- The Remove ads purchase with Restore purchases.
- `android-internal.yml`: a signed AAB on every push to `main`, uploaded to Play internal testing.
- Privacy policy text and Play Data safety answers in `docs/store/`.
- Gate: the build is in internal testing on Michael's phone, ads show test creatives, app-ads.txt
  on appcode.dk covers the app.

## Out of scope (each needs a plan change and Michael's yes)
Mediation and other ad networks; analytics, remote config or A/B tests; iOS, `release.yml`, the
production track and real ad unit IDs in a build (Phase 7); any new menu screen, meta or save
format (Phase 5); a banner in battle other than the pause foot; a rewarded or interstitial ad on
the pause menu; consumable purchases; the SDK in the dev and perf APKs.

## Test plan (what is proven headless)
- **Facade contract (P401):** a test pins every signal with its argument types, every method with
  its argument and return types, and `fake_auto_close`'s default, so Phase 5 can code against the
  stub and a later row cannot drift.
- **Caps (P402):** `AdCaps` table cases: matches 1 and 2 none, the 3rd after 240 s yes, 239 s no,
  twice for one match no, Remove ads none, no consent none; `play_seconds` adds up; a shown one
  resets the counter. Every number from the `.tres`, pinned literally in a data test.
- **Never waits for what has not shown (P403, P404):** under a fake backend that never answers,
  `ensure_consent` returns when `consent_timeout_ms` passes before the form shows, and
  `maybe_show_interstitial` and the rewarded show return false when `fullscreen_timeout_ms` passes
  before `ad_opened`. **Never-closing case:** once an ad or the form has shown, a backend that
  never closes keeps the await pending; the timeout does not fire, nothing proceeds under the ad,
  and `ad_closed` and the return come only with the close. An offer whose ad is not loaded is
  hidden; no spinner node exists. P421 is the end-to-end variant through Phase 5's flow.
- **Rewards (P403, P431-P433):** a reward only in the reward callback (close before it = no
  reward); the grant written before the close is handled (a call-order spy); one offer per screen.
- **Consent (P404):** a spy backend records no load and no initialise before "can request ads";
  offline and error paths end with ads unrequested; privacy options shown only when required.
- **Plugin seam (P405, P406):** `AdMobBackend`, `UmpPluginBackend` and `PlayBillingBackend` against
  duck-typed fake plugin objects: call order, callbacks mapped, `PENDING` never granted,
  acknowledge called, restore and refund.
- **Layout (P430, P435, P434):** the band at ADR 0015 §6's six sizes and the short profiles: the
  gap, collapse to 0, the height change and reload after a turn; the pause foot upright only where
  the foot is free, 16 dp to the Vibration chip, none sideways or scrolling, no banner object while
  the menu is closed; the rows at 48 dp.
- **Scans:** no `AdService` or `game/ads` in `game/sim`, `game/ai`, `game/core`; Poing and billing
  classes named only in their backends (P403); the ad ID guard over every tracked file (P420).
- **Guards narrowed, not deleted:** `tests/ui/support/hud_walk.gd`'s `ad_nodes` scans the root,
  autoloads included, so P401 exempts the node `/root/AdService` alone and asserts it holds no
  banner child (`test_hud_walk_scans.gd` and `test_hud_walk.gd` then pass unchanged). P435 allows
  `AdBannerBand` under `PauseMenu` in `ad_nodes` and in `tests/ui/test_pause_prefs.gd`'s
  battle-scene test, and asserts the fake showed no banner while the menu was closed.
  `tests/ui/test_result_screen.gd` allows only `DoubleXpOffer` in `OfferSlot` and still forbids
  banner and interstitial words (P432).
- **CI (P410-P414):** `test_export_presets.gd` pins the fourth preset; `test_ci_workflow.gd` pins
  `android-internal.yml`; `test_ci_balance_workflow.gd` the negation; offline tests of
  `version-code.sh` and `write-ad-ids.sh` (fake IDs built at run time).
- **End to end (P421):** fake mode through Phase 5's flow: consent, a menu band, five matches,
  interstitials only where the caps allow, a start bonus granted and taken once, a purchase, then
  no band and no interstitial, the offers still there; and every awaitable under a backend that
  never answers.
- **Not headless:** the real SDKs, UMP's form, billing and the Play upload. CI proves the AAB and
  the upload; P422 checks the rest on Michael's phone. No AI-vs-AI or timing run in a session.

## Risks
- **Unconfirmed plugin facts.** Not in the repository, to confirm in P410/P405: the Poing release
  for Godot 4.7.x (tag and commit), whether its Android part is a v2 AAR bundle per Godot version,
  its GDScript API names (expected `MobileAds`, `AdView`, `AdRequest`, `InterstitialAdLoader`,
  `RewardedAdLoader`, `UserMessagingPlatform`, from memory, unverified), how the App ID reaches
  the manifest, custom banner positions, the SDK versions it pulls, its licence. Billing (P411):
  the release for 4.7 and its Billing Library version against Play's minimum. Godot: the
  template-install switch and the AAB export option names. If no Poing release supports 4.7.2,
  P410 stops and reports (CLAUDE.md: never work around); a fallback is a new ADR.
- **godotengine/godot #123712** (ADR 0013): a shutdown crash after an export with AdMob and
  gdUnit4. P410 watches; a fix may need the export job to run without gdUnit4 in the tree.
- **Gradle in CI:** longer builds, Maven outages, cache size. Not in cloud sessions: their proxy
  refuses `dl.google.com` (ADR 0005, Context), which serves Google's Maven repository.
- **16 KB pages:** Play requires them for Android 15 targets; P410 checks the alignment.
- **The draft app:** API uploads may need `status: draft` until the first rollout, and the first
  upload is manual (M5).
- **SDK cost in battle is unmeasured:** the perf APK has no SDK. The pause banner is destroyed on
  close, so no ad object runs in play, but the SDK's resident threads do. A Play-preset perf
  variant (with `dev_menu`) is a follow-up for the lead's list, not a Phase 6 row.
- **Phase 5 timing:** the (b) rows, P421, P422 and the gate wait for Phase 5's menus; lanes M, R
  and T's (a) rows do not. Phase 5's menus wait for P430's band (wave 4).
- **AdMob account safety:** accidental clicks (the gap rules), live-ad taps (internal builds use
  test units; Michael's phone is a test device), consent outside the EEA (UMP decides).
- **Scope creep:** mediation, analytics, remote config, iOS stay out.
