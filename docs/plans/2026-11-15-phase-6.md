## Goal
- `AdService` with a fake mode that tests, the editor, the web preview and the dev APKs use; the
  Poing AdMob plugin on the Play build; caps from `data/ads_settings.tres`; gameplay never waits
  for an ad.
- UMP consent before any ad request; "Privacy options" in settings when UMP requires it.
- Rewarded offers by the player's choice (Double XP, +500 starting credits next match); a capped
  interstitial between matches; banners in the menus and at the open pause menu's foot.
- The Remove ads purchase with Restore purchases.
- `android-internal.yml`: a signed AAB on every push to `main`, uploaded to Play internal testing.
- Privacy policy text and Play Data safety answers in `docs/store/`.
- Gate: the build is in internal testing on Michael's phone, ads show test creatives, app-ads.txt
  on appcode.dk covers the app.

## Out of scope (each needs a plan change and Michael's yes)
Mediation and other ad networks; analytics, remote config or A/B tests; iOS, `release.yml`, the
production track and real ad unit IDs in a build (Phase 7); any new menu screen, meta or save
format (Phase 5); a banner in battle other than the pause foot; a rewarded or interstitial ad on
the pause menu; consumable purchases; the SDK in the dev and perf APKs.

**Gaps for the lead to agree with Phase 5** (each with the recommendation):
- **G1 Who shows the menu banner.** The facade has no show or hide. Recommended: add
  `show_banner(placement: StringName)` and `hide_banner(placement: StringName)`; each menu calls
  them on enter and leave (or instances Phase 6's `AdBannerBand`, which does both). Not: `AdService`
  watching `current_scene` (it cannot know a screen's band).
- **G2 A granted start bonus must survive until the match.** If the widget writes `MatchSetup`
  only in memory, an app kill between the reward and the match loses a granted reward (against
  "save the grant before resuming"). Recommended: the reward callback stores it in the `ads`
  section; Phase 5's match start calls `AdService.take_start_credits_bonus() -> int` (consumes
  once) into `bonus_starting_credits`. Item 5 then reads "set at match start", not "set by the
  widget".
- **G3 Licences.** Phase 5's Licences screen lists the Poing plugin's and the billing plugin's
  licence texts, which P410 and P411 put under `docs/licenses/` and into
  `THIRD_PARTY_LICENSES.txt`. Whether Google's SDKs need a notice is to confirm in P410.
- **G4 The gap.** 16 dp is the floor (`banner_gap_dp`); the start page keeps ADR 0025 §12's 48 dp.
- **G5 `play_seconds`** is the match's sim time (ticks / 15) and is sent only for a match that
  ended (win, loss, surrender), not for Exit to menu mid-match.
- **G6 Slots.** Each slot is a plain `Container` named for its placement (`OfferSlot` on the
  result screen and map select, `PurchaseSlot` in settings); the widget is its only child and the
  slot takes the child's minimum size (0 when hidden). One offer per screen.
- **G7 Guard tests.** `tests/ui/test_result_screen.gd`'s no-ad test is narrowed by P432, not
  deleted; Phase 5's own no-ad scans allow the band, the slots and the `AdService` calls above.

## Risks
- **Unconfirmed plugin facts.** Not in the repository, to confirm in P410/P405: the Poing release
  for Godot 4.7.x (tag and commit), whether its Android part is a v2 AAR bundle per Godot version,
  its GDScript API names (expected `MobileAds`, `AdView`, `AdRequest`, `InterstitialAdLoader`,
  `RewardedAdLoader`, `UserMessagingPlatform`, from memory, unverified), where the App ID goes,
  custom banner positions, the SDK versions it pulls, its licence. Billing (P411): the release for
  4.7 and its Billing Library version against Play's minimum. Godot: the template-install switch
  and the AAB export option names. If no Poing release supports 4.7.2, P410 stops and reports
  (CLAUDE.md: never work around); a fallback is a new ADR.
- **godotengine/godot #123712** (ADR 0013): a shutdown crash after an export with AdMob and
  gdUnit4. P410 watches; a fix may need the export job to run without gdUnit4 in the tree.
- **Gradle in CI:** longer builds, Google Maven outages, cache size. Not in cloud sessions.
- **16 KB pages:** Play requires them for Android 15 targets; P410 checks the alignment.
- **The draft app:** API uploads may need `status: draft` until the first rollout, and the first
  upload is manual (M5).
- **SDK cost in battle is unmeasured:** the perf APK has no SDK. The pause banner is destroyed on
  close, so no ad object runs in play, but the SDK's resident threads do. A Play-preset perf
  variant (with `dev_menu`) is a follow-up for the lead's list, not a Phase 6 row.
- **Phase 5 timing:** the (b) rows, P421, P422 and the gate wait for Phase 5's menus; lanes M, R
  and T's (a) rows do not.
- **AdMob account safety:** accidental clicks (the gap rules), live-ad taps (internal builds use
  test units; Michael's phone is a test device), consent outside the EEA (UMP decides).
- **Scope creep:** mediation, analytics, remote config, iOS stay out.
