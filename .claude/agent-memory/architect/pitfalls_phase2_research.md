Measured headless in a scratch project on the cloud VM (Xeon 2.1 GHz). **Why:** they decide sim rules and the perf budget. **How to apply:** reuse instead of re-spiking; treat phone numbers as unverified until the perf arena runs.
- int64 add/mul overflow wraps silently (C++ UB); `1 << 64 == 1`; a constant negative `>>` operand is a parse error, runtime `-8 >> 1 == -4`.
- PackedInt32Array silently truncates stores to int32 (2^31 -> -2^31): never store squared distances there.
- HashingContext SHA-256 of ~10 KB state: 0.07-0.10 ms; GDScript FNV loop: 0.3-0.5 ms. var_to_bytes round-trips Dict with PackedInt32/Int64Array.
- FixedMath.isqrt (digit loop) about 2 us per call: 150 calls per tick = 0.3 ms.
- Array literal inside a loop (`[1, -1][k]`) allocates each pass: 64x64 Dijkstra 17-20 ms vs 3-4 ms with const offsets and a padded grid.
- Mock 150-unit tick: separation with 2-tile cells 1.3 ms vs 1-tile 0.23 ms; full-disc fog 0.69 ms vs incremental per-player 0.12 ms; optimised mock tick 0.7 ms mean, 1.25 ms p95.
- (Documented, not spiked) z_index sorts all canvas items of a CanvasLayer before tree order: a relative negative z on a child can draw under the map; use absolute z per world layer.
- (Plan review 2026-10-11) Godot draw calls under Compatibility: filled draw_rect, draw_line, draw_texture_rect batch; draw_circle/arc/polyline/unfilled rect/polygon cost one call each; Phase 1 Ring = 6 calls. Absolute z: 150 rigs 360 -> 13 calls. viewport_get_measured_render_time_cpu works in Compatibility.
- (Plan review) `"%016x" % negative` prints a minus sign; use encode_s64 + hex_encode. GDScript `+` binds tighter than `<<`. PackedInt32Array has no pop_back and stores 0xFFFFFFFF as -1.
- (Plan review) Real hash state ~86-109 KB costs 0.34-0.38 ms; fog restamp 23-26 us/unit; full 64x64 fog texture rebuild 0.75 ms; 1024-cell Dijkstra slice 1.1-1.5 ms; counting-sort grid rebuild 0.32-0.40 ms vs head/next 0.046 ms; Formation.assign 75 units ~1 ms, 150 units 3.15 ms; aliasing World arrays into locals is 2.7x faster, inline fog lookup 5.6x.
- (Plan review) CI noise: busy runner leaves p50 alone but p95 jumps ~9x (4 ms scheduler slice); enforce min-of-3 and deterministic counters, not single-run p95.
- (Pitfall) Plans that keep Phase 1 tests "unchanged" must check hand-built World.new() helpers in tests (no rules, no player_count, no max_hp) and qa-owned pinned bounds; a typed member referencing a class from a later PR is a parse error.
- (Completeness check) Godot 4.7.2 headless: clipboard_get() logs an ERROR (verify RED), screen_is_kept_on() stays false, ImageTexture.get_image() after update()/set_image() returns the first upload; Engine.max_fps reads back. Plan Callable sinks and CPU-side image() accessors for tests.
- (Completeness check) Size estimates must be counted from listed contents (members, lists, test cases), not asserted; the sqrt-free push d*(R^2-d^2)/2R^2 is 0 at d=0, so coincident-ish pairs need their own rule.
- (Second check) "Phase 1 tests stay green" claims need an audit of every test with run_ticks/Sim.step and 2+ units, including other owners' files (test_player_controller and test_unit_layer repeated test_controls_flow's order); separation proto on controls_test: max centre 3794, min pair 801, all idle tick 155 for the (22250,22250) order. Re-aim view tests to corner tanks rather than weakening them.
- (Second check) A probe/enum consumed across owners needs fixed ids + COUNT + names in the contract, or per-phase numbers drift between PRs.
- (Third check) The Phase 1 test audit must cover view/input/UI tests too: tests pin node names, child order and inner-class properties (Ring.radius/.unit), and fog hiding turns Phase 1 enemy taps into ground taps; hand-built snapshots lack new arrays.
- (Third check) Never let a PR that sets measured bounds (P49) precede a PR that adds the measured work (fog); order them or name the exact constants a later PR may move.

- (ADR 0012, verified 4.7.2 headless 2026-10-12) Packed arrays alias by reference (b = a; b[0] writes a); duplicate() is lazy COW; the first later write reallocates (size + 32 B) at ~0.03 ns/byte for <=32 KB arrays (revision 1's 0.6 ns/byte was a 4 MB case). Thread + two Semaphores: one post = one token (try_wait true once); frame-paced main side p95 <0.1 ms, worker wake p95 ~0.18 ms (hot-loop 40 us is not the figure to quote). WorkerThreadPool high prio: job p95 +12 %, main stalls 1.4 ms. OS.has_feature("threads") true headless; DisplayServer.get_name() == "headless"; web preset thread_support=false.
- (ADR 0012, corrected by review) Unjoined started Thread: WARNING at free, but a worker still blocked at exit gives `ERROR: 1 resources still in use at exit` (verify red, no pointer); wait_to_finish() on an unstarted Thread logs ERROR; a never-added Node gets only NOTIFICATION_PREDELETE on free -> join in _exit_tree AND PREDELETE, only if is_started(). Worker write to an IN-TREE Node: editor/debug template refuse with ERROR, release silent (my 'logged nothing' test used a node outside a running tree) -> a headless WORKER scene run is a real guard on debug. MEMORY_STATIC reads 0 on release.
- (ADR 0012 review, measured) Cross-thread `obj.prop` reads serialize: both threads 2-4x slower (typed h.arr[i] x2-3, Node2D.position set x4-8); aliased locals unaffected; real Formation.assign x1.8 next to rig moves. Debug/editor also serialize calls. Rule: alias before loops on BOTH threads. Debug->release on CI: mock tick x1.33 mean; phone release mock on worker est. 10.4-13.3 ms p95 vs 13.3 limit; the ADR 0008/0011 tick estimates were 3.3x low.
- (ADR 0012 pitfall) A late-tick rule that counts 'job not done at the boundary' counts main-thread hitches (first frame after load, any >2-period frame); count post-to-done > period on the worker instead, and drop the backlog after one publish. Semaphore tokens are consumed once: a wait outside RUNNING state hangs, and gdUnit's timeout cannot fire while main blocks -> timed try_wait loops.
- (ADR 0012 pitfall) A device-derived CI ceiling (limit / phone ratio) can sit below the ADR 0011 floor (1.5 x min-of-3) -> unmergeable budget that blocks the gate path; enforce a ratchet on CI and print the phone estimate. Audit tests that write the World after the last tick when moving the view to a copy-based snapshot.
- (ADR 0012, Xvfb/llvmpipe, 150 sprites one absolute z) 1 texture+1 tint: 1 call; alternating tints: 150; 3 textures interleaved (mixed unit types): 150; one z per texture: 3; one z per tint: 2. Colours inside one _draw() do not break batches (probe bars/effects). The P26s probe used tank art only, so type interleave was unmeasured there.
- (ADR 0012 pitfall) A parallel session can open/split a PR (P27b -> P27c, kept 512) while a plan amendment is drafted: re-check git log / memory for in-flight PRs before assigning a value change to an unmerged PR.
- (Verified 4.7.2 headless 2026-10-12) Assigning to a getter-only script property (`var w: int: get: ...`) is silently ignored, no error: every guarded property used by tests needs a setter, or swap/probe-install tests pass vacuously.
- (ADR 0012 completeness pitfall) A revision that grows PRs must re-check the >=330 split rule for every row it touched; and withdrawing a rule (ceiling) must also withdraw its sibling start values (4.0 ms) and role-file text, or an agent hits the old rule literally.
- (ADR 0012 pitfall) A field a method reads (capture compares match_serial) must be set BEFORE the call; 'set right after' kills the branch silently -> pin the order in the ADR and add a test that fails on the wrong order (consecutive ticks give prev != pos).
- (ADR 0012 pitfall) Worker tests driving _process(delta) advance a virtual clock in microseconds while jobs take real ms: any case asserting no hold / one publish per boundary must wait_idle() after each frame, or it is flaky on CI. Agent-file changes are their own owner question; an ADR yes does not cover them.
- (ADR 0012 nits) A "pure" transition table must not hide I/O in a cell ("try_wait(); taken ->"): make the poll result an event. A test helper that blocks the worker needs its own capped wait plus an after_test release, since wait_to_finish() has no timeout. Never compare a run with commands to a run without; compare equal inputs (replay the recorded log).
- (ADR 0012 nits) When a PR is split, every Depends cell that needs the moved content must name the part (or a lane rule must say "Px means all parts"); and contract text must not name fields (private, guarded) before the PR that creates them.
- ADR 0012 §5 flow rule has two halves (2 ms cap AND worker-p95 headroom <= 12.0 ms); never quote the cap alone as "the rule's value" without the headroom check. In-frame numbers are not the worker numbers the ratios are defined on: record them as provisional until the worker-mode run.
